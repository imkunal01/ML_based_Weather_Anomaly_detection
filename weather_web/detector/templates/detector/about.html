End-to-End System Pipeline

Phase 1
Data Ingestion & Cleaning

Historical hourly telemetry collected across 3 years (2023-2025) via the Open-Meteo API. Data is filtered to eliminate physically impossible extremes and split chronologically into training (history) and holdout (test) partitions.

Phase 2
Model Training & Scoring

Trained with StandardScaler and an Isolation Forest of 200 decision trees. Anomalous instances are isolated close to tree roots with shorter path lengths, generating high anomaly scores.

Phase 3
Interactive Web Platform

A clean Django interface enabling operators to upload datasets, review interactive Chart.js time-series plots, inspect anomaly rankings, and conduct real-time single-sample sensor simulations.

Model Architecture & Hyperparameters

Component Configuration / Value Engineering Purpose
Algorithm Isolation Forest (iForest) Unsupervised anomaly detection without needing labeled ground-truth data.
Feature Set temp, humidity, pressure, wind, rain Captures multi-dimensional correlations across all meteorological sensors.
Feature Normalization StandardScaler (Zero mean, unit variance) Ensures distance metrics and tree partitions treat each sensor dimension equitably.
Ensemble Estimators 200 Trees Ensures stable average path length calculations and mitigates random split variance.
Contamination Rate 0.02 (2%) Calibrated expected outlier proportion in historical climate station data.

Key Talking Points for Viva & Professor Evaluation

Fixed thresholds cannot detect multi-sensor inconsistencies. For example, a reading of Temperature = 35°C, Relative Humidity = 99%, and Barometric Pressure = 850 hPa with no rain represents a physically suspect anomaly even though every individual measurement falls within its standard individual bounds. Isolation Forest analyzes all dimensions concurrently.

The Django application acts as a presentation and management tier. It cleanly imports the existing ML model wrapper without modifying any core model code. User-uploaded CSV datasets are validated, passed to the model inference function, and the returned predictions and anomaly scores are stored in SQLite and presented through Chart.js visualizations.

The anomaly score provides a continuous measurement of how isolated a data point is in tree space. Instead of a binary yes/no, operators can prioritize investigation based on severity, sorting and addressing extreme sensor failures first.
